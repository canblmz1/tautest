# Phase 3 CLI Report

## Goal

Build a user-friendly `tautest` CLI package on top of `@tautest/core` without copying core logic into the CLI and without adding a GitHub Action.

## What Was Built

- `packages/cli`
  - TypeScript CLI package.
  - ESM build through `tsup`.
  - `tautest` binary entry.
  - Commander-based command routing.
  - Vitest tests for command registration, `init`, `prompt`, and `report`.
- CLI commands
  - `tautest init`
  - `tautest doctor`
  - `tautest run`
  - `tautest prompt`
  - `tautest report`
- Root workspace support
  - Added `packages/*` and `examples/*` to `pnpm-workspace.yaml`.
  - Added the local `tautest` CLI workspace package as a root dev dependency so `pnpm exec tautest` works during local development.

## Command Behavior

### `tautest init`

- Detects project, package manager, and test runner through `@tautest/core`.
- Creates `tautest.config.ts`.
- Adds `.tautest/` to `.gitignore`.
- Adds required Stryker dev dependencies:
  - `@stryker-mutator/core`
  - `@stryker-mutator/vitest-runner` or `@stryker-mutator/jest-runner`
- Supports:
  - `--yes`
  - `--no-install`
  - `--runner`
  - `--pm`
- Uses file snapshots for safe rollback if initialization fails before completion.

### `tautest doctor`

Checks:

- Node.js version
- Git availability
- Git repository status
- shallow clone status
- `package.json`
- test runner
- Stryker dependencies
- Vitest/Jest config
- monorepo signals
- existing Stryker config
- `.tautest/` gitignore status
- package manager

Supports `--json`.

### `tautest run`

- Loads `tautest.config.*`.
- Reads Git diff from the selected base ref.
- Filters changed production source files.
- Maps changed ranges to Stryker mutate strings.
- Runs Stryker programmatically through `@tautest/core`.
- Writes:
  - `.tautest/report.md`
  - `.tautest/report.json`
  - `.tautest/fix-prompt.md`
  - `.tautest/mutation.json`
- Supports:
  - `--base`
  - `--threshold`
  - `--ai`
  - `--max-files`
  - `--report-dir`
  - `--no-cache`
  - `--config`
  - `--json`
  - `--dry-run`

### `tautest prompt`

- Reads `.tautest/report.json` by default.
- Supports `--from`.
- Prints an AI test-fix prompt to stdout.
- Reuses the same prompt command list generated by `tautest run`.

### `tautest report`

- Reads `.tautest/report.md` by default.
- Supports `--from`.
- Prints markdown report content to stdout.

## Exit Codes

- `0`: successful run and threshold passed.
- `1`: successful run but threshold failed.
- `2`: no changed production source files.
- `10`: config error.
- `11`: detection error.
- `12`: Stryker error.
- `20`: Git error.

## Core Support Added During Phase 3

- `readGitDiff` can run with `--relative` so package-root CLI runs produce Stryker-friendly paths.
- Git diff stderr is piped to prevent harmless Git line-ending warnings from polluting normal CLI output.
- Stryker config generation explicitly loads the Vitest/Jest runner plugin. This avoids pnpm plugin discovery issues in workspace installs.
- Stryker log output is minimized for the CLI path.
- Config loading supports a package alias so `tautest.config.ts` can import `@tautest/core` even when the user project only invokes the CLI package.
- Package manager detection can use parent workspace metadata when a package has no local lockfile or `packageManager` field.
- Project detection reports ancestor monorepo signals as warnings while still keeping the current package as the execution root.

## Example Validation

Validated in `examples/vitest-basic`.

Commands run successfully:

```bash
pnpm test
pnpm typecheck
pnpm build
pnpm exec tautest init --yes --no-install --runner vitest --pm pnpm
pnpm exec tautest doctor
pnpm exec tautest run --base HEAD
pnpm exec tautest prompt
pnpm exec tautest report
```

Observed `tautest run --base HEAD` result:

- Verdict: `MIXED`
- Mutation score: `75.00%`
- Killed: `3`
- Survived: `1`
- No coverage: `0`
- Top surviving mutant: `src/discount.ts:2`, `age >= 65` -> `age > 65`

Generated files:

- `examples/vitest-basic/.tautest/report.md`
- `examples/vitest-basic/.tautest/report.json`
- `examples/vitest-basic/.tautest/fix-prompt.md`
- `examples/vitest-basic/.tautest/mutation.json`

`tautest doctor` reports one warning in the example because the package is inside the repository workspace. This is expected for Phase 3: monorepo support remains detect-and-warn only.

## What Worked

- `npx`/`pnpm exec` style local binary usage works through the package `bin` entry.
- `tautest init` is idempotent in the example project.
- `tautest run` executes the Stryker programmatic API and produces all expected output files.
- The generated fix prompt points the agent at the missing boundary test and forbids production-code changes.
- Terminal output stays short and focused.
- JSON output is available for `doctor` and `run`.

## What Was Not Built

- No GitHub Action.
- No cloud/dashboard workflow.
- No full monorepo orchestration.
- No Jest execution validation.
- No package publishing workflow.
- No external AI agent execution. `--ai` remains prompt-generation oriented in this phase.

## Remaining Risks

- Stryker programmatic execution still depends on Stryker's current public API behavior.
- The core Stryker runner changes `process.cwd()` during execution; do not run multiple mutation jobs in parallel in the same process yet.
- Jest is wired at the detection/config level but not validated end-to-end.
- Monorepo handling is advisory only. The CLI should not yet orchestrate many packages or workspace dependency graphs.
- `init` rollback protects local file edits, but package-manager installs can still leave lockfile churn if an install fails midway.
- Package manager detection from parent directories is best effort and should stay transparent in `doctor`.

## Assumptions

- Phase 3 can add a local workspace CLI package without publishing it.
- Vitest remains the only end-to-end validated runner for this phase.
- The example package is allowed to live inside the repo pnpm workspace as long as Tautest executes from the package root.
- `tautest.config.ts` should be user-editable but generated conservatively.
- The CLI should create prompts and reports, not call Claude/Cursor/Codex directly.
